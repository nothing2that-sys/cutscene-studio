# LLM 샷 패키지 (zip)

촬영 미리보기의 **LLM 패키지 (zip)** 버튼은 현재 컷을 촬영 카메라 한 대로 분해해서 GPT·Gemini 같은 이미지 생성 LLM에 그대로 올릴 수 있는 묶음을 만듭니다. 사람이 보는 3D 뷰와 컬러 렌더는 앱에서 그대로 쓰고, LLM에는 구도·거리·명암·포즈를 나눈 자료를 줍니다.

```
shot-<컷 이름>/
  prompt.txt     작화 지시문: 파일 읽는 법, 라벨 색 ↔ 인물·설정화, 포즈·조명 문장
  shot.json      모든 수치와 범례
  color.png      무채색 마네킹 렌더 (구도 확인용, 그림자 포함)
  label.png      객체별 단색 (배경 검정, 바닥 #505050, 벽 #8c8c8c)
  depth.png      카메라 거리 8bit: 가까움 255(흰색) → 멂 40, 배경 0
  depth16.png    카메라 거리 16bit, 단위 mm, 배경 0 (ControlNet 등 수치 입력용)
  light.png      주광의 직사광만: N·L × 그림자, 주변광 제외
  pose.png       인물별 뼈대: 인물 기준 왼쪽=밝은 색, 오른쪽=어두운 색, 가려진 관절=빈 점·점선
  refs/<객체 id>/<n>-<종류>.png|jpg   연결한 설정화
```

## 화풍

지시문 맨 앞에 화풍을 적고, 첨부 이미지는 그림체 참고가 아니라 구조 자료라고 못박습니다. 이미지 생성 모델은 회색 렌더·뎁스·라벨 이미지를 여러 장 받으면 그 질감을 따라 실사·3D로 그리는 경향이 있습니다(나노바나나에서 확인).
- 장면 JSON의 `style`(문자열, 최대 2000자)이나 패널의 「화풍」으로 지정합니다.
- 비워 두면 `2D 웹툰 일러스트: 깨끗한 검은 선화와 셀 채색(2~3단 명암). 사진·실사·3D 렌더·CG 질감으로 그리지 않음.`을 씁니다.

## 지시문 구성 (2026-11-06 비교 실험 반영)

`prompt.txt`는 다음 순서로 짧게 씁니다.
- 화풍
- 지킬 순서: 구도 → 크기·거리(depth) → 명암·그림자(light) → 포즈·좌우(pose) → 외형
- 마네킹 따라 그리기 금지
- 카메라·조명, 인물 목록, 원문

[비교 실험](LLM_ABLATION_PROCEDURE.md)에서 확인한 내용을 반영했습니다.
- **depth.png는 인물 크기와 거리감을 확실히 바로잡았습니다.** 그래서 카메라에서 가까운 순서와 거리를 함께 적고, "먼 인물을 키우지 말 것"을 명시합니다.
- **설명 문장만 늘리는 것은 효과가 없었습니다.** 그래서 같은 포즈 문장을 두 번 쓰던 「장면 설명」 블록과 비어 있는 "설정화: 없음" 줄을 뺐습니다.
- **벽 그림자가 마네킹 몸매로 그려졌습니다.** 그래서 그림자는 그린 인물의 실루엣으로 그리라고 적습니다.


- **뎁스**: 카메라 중심에서 표면까지의 직선거리(m)입니다. 8bit 범위는 화면 안 인물·소품의 가장 가까운 지점에서 0.3m 앞부터 가장 먼 지점에서 0.5m 뒤까지로 맞춥니다. 그래서 인물들이 회색 단계를 넓게 나눠 씁니다. 범위 밖의 바닥·벽은 끝값으로 고정됩니다. 실제 범위는 `shot.json › depth.depthPng.nearM/farM`에 있습니다.
- **조명 종류** (장면 JSON `lighting.type`, 패널의 「조명 종류」)
  - `sun`(기본): 평행광입니다. `position → target` 방향으로 장면 전체에 같은 세기로 비추고, 그림자가 평행하게 떨어집니다.
  - `lamp`: 전등(점광원)입니다. `position`에서 사방으로 퍼지고 거리 제곱에 반비례해 어두워집니다. 그림자는 광원 반대쪽으로 방사형으로 퍼집니다.
  - `spot`: 스포트입니다. `position`에서 `target` 쪽 원뿔로만 비춥니다. `coneDeg`(전체 각도, 기본 50)와 `softness`(가장자리 부드러움 0~1, 기본 0.3)를 지정합니다.
  - `intensity`는 **비추는 곳(target)에 도달하는 밝기**입니다. 그래서 종류를 바꿔도 target 주변 밝기는 비슷하게 유지됩니다.
  - 편집 화면에는 광원 위치(노란 점)와 비추는 곳까지의 점선이 보입니다. 이 표시는 촬영에서 빠집니다.
- **light.png**: 직사광만 보여 줍니다. 빛을 정면으로 받는 면은 흰색이고, 빛을 등진 면과 다른 물체의 그림자 속은 검은색입니다.
  - 전등·스포트는 target 지점의 밝기를 흰색 기준(1)으로 삼습니다. 그보다 가까운 곳은 흰색으로 포화되고, 먼 곳은 회색입니다.
  - 촬영 렌더에서는 인물도 그림자를 드리웁니다(편집 화면은 기존처럼 꺼 둠).
- **인물별 조명 판정** (`labels[].lightCondition`)
  - `facingLight`: 몸 정면과 빛 방향의 일치도. 1이면 정면광, −1이면 역광입니다.
  - `cameraSeesLitSide`: 카메라가 밝은 면을 보는지 나타냅니다.
  - `castShadowFrom`: 머리·가슴·골반·손·무릎에서 빛 쪽으로 광선을 쏴서 막는 물체를 기록합니다. 예: `{"인물1":["head","chest"]}`
  - `directLight`: label 영역 안에서 계산한 실제 직사광 비율입니다.
  - 전등·스포트일 때만 추가되는 값
    - `distanceToLightM`: 광원까지의 거리
    - `brightnessVsTarget`: target 대비 밝기, (기준거리/거리)²
    - 광원이 머리보다 낮으면 "아래에서 올려 비춤"이라고 적습니다.
    - 스포트는 `inCone`(inside / edge / outside)도 기록합니다.
  - 광원이 화면 안에 있으면 `lighting.source.xy`에 화면 위치가 들어갑니다.
- **광원 위치** (`lighting.source`): 인물들보다 앞/사이/뒤(`relation`), 카메라 거리, 높이, 화면 위치를 적습니다.
  - pose.png에는 광원이 화면 안이면 노란 해 모양, 밖이면 가장자리에서 들어오는 노란 화살표로 표시합니다.
  - 해(sun)는 실제 방향으로 멀리 투영해 화면 안에 들어오면 그 위치에 표시합니다.
- **포즈**: `labels[].pose.joints`에 관절별 화면 좌표(0..1, 좌상단 원점), 카메라 거리, 가림 여부가 들어갑니다. 왼쪽·오른쪽은 인물 자신 기준입니다.

## 설정화 연결

스튜디오 패널의 **설정화 · 레퍼런스 연결**에서 인물·소품마다 이미지를 붙이고 종류(전신·얼굴·의상·헤어·표정·소품·기타)와 메모를 적습니다.

- 2048px 또는 3MB를 넘는 이미지는 JPEG로 줄여서 저장합니다.
- 연결 정보는 객체 id(`studioId` / 소품 `id`) 기준이라 라벨 색과 짝이 맞습니다.
- 프로젝트 **Save** 파일의 `characterReferences`에 함께 저장되고 Load하면 복원됩니다.
- 실행 취소 기록에는 넣지 않으므로, 이미지가 커도 편집 성능에 영향이 없습니다.

## 미리보기

촬영 미리보기의 **미리보기 패스**에서 라벨, 뎁스, 직사광·그림자, 포즈 뼈대를 바로 확인할 수 있습니다. 기존 **Depth PNG** 버튼과 LLM 전달 묶음의 depth도 같은 카메라 거리 기준을 씁니다.

## 한계

- 주광은 하나만 다룹니다(+ 주변광). 여러 광원, 반사광, 광원 크기에 따른 부드러운 그림자는 없습니다.
- 라벨은 객체 단위입니다. 신체 부위는 pose.png와 관절 좌표로 전달합니다.
- 이미지 생성 LLM은 PNG를 그림으로 봅니다. depth16.png 같은 수치 파일은 수치 입력을 받는 생성기용입니다.
