## 2. Risks

### 2a. Verified

| # | Severity | Finding | Evidence | Fix |
|---|---|---|---|---|
| R1 | **High** | **Character sheets from the previous project leak into the next one.** `references` is a closure variable. It is replaced only when the restored state carries `characterReferences`. Opening a new scene JSON (`loadScene`) or an older project file without that key keeps the old images. If an id repeats (e.g. `actor-…` is random, but scene ids like `jihoon` and GLB prop ids `prop-1` repeat across projects), the old sheets are zipped as `refs/<id>/` and paired with the wrong person's label colour. | `studio.js:35`, `studio.js:485` (`restoreReferences` only), `main.js:185` (`if(state.characterReferences)`), `studio.js:283-284` (loadScene builds state without the key) | In `loadScene`, and in `applyState` when it comes from Load (not undo), reset `references={}` unless the state has the key. Alternatively, drop references whose id is not in the new scene, and report which ones were dropped. |
| R2 | **High** | **No crash/close protection** (see feature 1). Character sheets are also kept out of undo history, by design (`studio.js:33-34`), so they exist only in memory until Save. | grep shows no `beforeunload` or IndexedDB in `app/src` | See feature 1. |
| R3 | Medium | **Undo history holds full GLB base64 for every entry.** Each `captureState` stringifies the whole state: every imported GLB's `glbBase64` plus studio `document` and `initialProposal` (each with up to 12 000-char `sourceText`). It keeps 30 entries. Each capture also `JSON.parse`s the previous entry **twice** to compare. A 10 MB GLB means about 300 MB of strings in history, and every pose drag that ends parses 20 MB. | `main.js:118-127`, `main.js:143-149`, `studio.js:486` | Keep GLB bytes in a `Map<hash, base64>` outside history and store only the hash in snapshots. ### 2b. Suspicions (not reproduced)

| # | Severity | Suspicion | Evidence | How to confirm / fix |
|---|---|---|---|---|
| S1 | Medium | **Undo/redo during a body-type mesh build is not guarded.** If a state needs a body type that is not built yet, `applyState` returns `ensureBodyTypes(...).then(()=>applyState(json))` **without** setting `pendingRestore` or bumping `restoreGeneration`. `restoreHistory` sets `historyIndex=index` immediately. So during the build (a) the click/input guard at `main.js:1335` is not active and the user can keep editing, and those edits then get overwritten, and (b) two quick undos both resolve in completion order, not request order. | `main.js:160`, `main.js:217`, `main.js:1335` | Browser check: switch an actor to `male-heavy` on a cold page, then press Ctrl+Z twice fast. Fix: set `pendingRestore` to the build promise and increment `restoreGeneration` before the async wait. In the `.then`, drop the result if the generation changed. |
| S2 | Medium | **Walls and floor never cast shadows in light.png or `lightCondition`.** Only person/prop meshes get `castShadow` (`llm-package.js:61`), and the shadow raycast checks only person/prop meshes (`:182`). With a sun or lamp placed outside the room, the interior reads fully lit, but the colour render (where walls might shadow) can differ. There are no windows, so "sunlight through a window" cannot be shown correctly. | `llm-package.js:61`, `llm-package.js:182`; `studio.js:236` (walls `receiveShadow` only) | Render one case with the light behind the back wall and compare color.png with light.png. | S3 | Low-medium | **pose.png has no way to show a figure's facing when the head is out of frame.** Name tags are anchored at `headTop`. With a low-angle or partial shot, the tag lands off-canvas and is clamped to the edge, which may put it next to the wrong person. | `llm-package.js:154`, `:167-169` | Check a knee shot with two people. Anchor the tag at the highest **in-frame** joint instead. |
| S4 | Low | **`createShotPackage` renders color.png and the passes separately.** `renderPNG(false)` then `computePasses()` each call `beforeCapture` and `updateShotCamera`. ### 2c. Paths with no tests

Each of these code paths has no test today.

- **Character references:** save/load, restore, prune and id remapping (R1, R6). No script mentions `characterReferences` or `restoreReferences`.
- **`buildPrompt` with more than 18 labels**, or with hidden people, or without a `cameraLine`. `llm-package.test.mjs` covers the normal case only.
- **Undo/redo across a body-type switch** (S1), and undo while a GLB restore is in progress.
- **The validator copies matching** (R8).
- **Lamp/spot placed outside the room**, or behind a wall (S2).
