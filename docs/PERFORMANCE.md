# 편집 성능과 단독 포즈 모드

**포즈 잡기**는 기본으로 선택 인물만 그립니다. 다른 인물·소품·방·바닥은 편집 화면에서 숨기며 데이터를 삭제하지 않습니다. 목록에서 인물을 바꿀 수 있습니다. **인물 이동**으로 나가거나 **포즈는 선택 인물만**을 해제하면 전체 장면과 이전 작업 카메라를 복원합니다. 구도 저장·화각 편집은 전체 화면에서 합니다.

**가벼운 화면**은 기본 켜짐입니다. 편집 버퍼를 최대 1024×768에 맞추고 그림자를 끄며 변경된 화면만 최대 30fps로 그립니다. 입력이 없으면 GPU 그리기를 멈춥니다. 체크를 끄면 창 크기 해상도와 편집 그림자를 사용합니다. 설정은 현재 브라우저에 보관합니다.

촬영 미리보기도 변경이 있을 때만 갱신하고 단독 포즈 작업·드래그 중에는 멈춥니다. 필요하면 **미리보기 갱신**을 누릅니다. **PNG 캡처 / Depth PNG**는 전체 촬영 장면을 별도 렌더러에서 기존 해상도·그림자로 출력합니다. 편집 품질과 단독 모드는 출력 PNG·프로젝트 저장 내용에 적용하지 않습니다.

직접 IK는 움직인 목표만 계산하고 프레임별 탐색을 8회로 나눕니다. 도달하거나 오차 개선이 멈추면 같은 목표를 반복 계산하지 않습니다. 관절 영향 범위의 행렬만 갱신하며 길이·관절 범위·한 단계 회전 제한을 유지합니다.

## 전후 측정

`scripts/performance-check.mjs`: 예제 인물 6명, 창 1600×1100, 포즈 모드에서 2.5초 정지와 2.5초 카메라 이동을 측정합니다. 변경 전은 `2f2e3bf`, 변경 후는 소스 서버 3002입니다. Intel Iris Xe/D3D11와 강제 SwiftShader를 각각 사용했습니다. SwiftShader는 비교 실험이며 사용자 크롬 설정이라는 뜻이 아닙니다.

이전은 593 draw calls·121,428 triangles, 1600×1100 버퍼였습니다. 단독·가벼운 화면은 97 calls·20,220 triangles, 1024×704입니다. 최종 수치는 [증거 폴더](review-evidence/2026-11-02-performance/)에 있습니다. `averageRenderCpuMs`는 render 호출 벽시계 시간이며 GPU 실행 시간이나 전체 IK 지연이 아닙니다. 장치·환경 부하에 따라 FPS가 달라지며 특정 속도를 보장하지 않습니다.

## PC 확인

**렌더링 정보**에서 장치 이름·편집 해상도·그림자·그리기 호출을 확인하세요. SwiftShader/Software가 표시되면 소프트웨어 렌더링이 감지된 것입니다. 시험용 크롬에서는 Intel Iris Xe가 확인됐으나 사용 중인 크롬 프로필의 설정까지 확인한 결과는 아닙니다. 그래픽카드 유무만으로 원인을 확정하지 않습니다.

최종 캡처·포즈 썸네일 생성 시의 부하는 남습니다. 전체 CPU 사용률·전력·실제 손 드래그 체감·다른 브라우저는 이번 자동 검사의 측정 범위가 아닙니다.
