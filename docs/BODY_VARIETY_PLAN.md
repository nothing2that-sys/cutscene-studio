# 체형 다양화 계획

2026-11-10. [BODY_REDESIGN_PLAN.md](BODY_REDESIGN_PLAN.md) 4단계("체형 확장과 앱 통합")의 구체화다. 아직 구현하지 않았다.

## 왜 필요한가

앱의 인체는 최종 그림이 아니라 이미지 생성 모델에 넘기는 **구조 자료**다. 체형이 하나뿐이면 다음 문제가 생긴다.

| 문제 | 실제 사례 |
|---|---|
| 아이·작은 체구를 표현할 수 없음 | 5.5등신을 지정하면 이전 버전 몸체로 바뀌어 모양과 리그가 달라짐(E2 실험) |
| 남성을 여성 마네킹으로 렌더 | E2의 "50대 남성"이 가슴·엉덩이 곡선이 있는 마네킹으로 나옴 |
| 마네킹 체형이 그림에 새어 나옴 | E1 벽 그림자가 마네킹의 가슴·엉덩이 윤곽 그대로 그려짐(c1 3/3) |
| 무릎 꿇기 등 자세 프리셋 없음 | 홀리데이 장면의 무릎 꿇기를 관절값 조합으로 근사 |

목표는 해부학적으로 정밀한 인체가 아니라, **키·등신·성별·체격 차이가 실루엣과 뎁스에서 읽히는 구조 모형**이다.

## 현재 구조 (조사 결과)

- **형상은 숫자로 만든다.**
  - v1 인체는 `fullDollDesign()`과 `dollProfile()`의 매개변수로 생성된다. 매개변수는 단면 행 [높이, 폭, 앞, 뒤], 소켓 위치·반지름, 팔다리 길이, 어깨 폭, 머리 크기·위치다.
  - 메시는 `doll-core-worker`가 설계값에서 계산한다. 기본 체형만 `public/doll-full-core/preview.bin`으로 미리 구워져 있다.
- **제약은 리그와 저장 포맷에 있다.**
  - `createCharacter`는 `headUnits!==8`이거나 `chest`가 있으면 이전 버전 몸체(legacy-male-v7)를 만든다.
  - `validateBodyV1State`는 `rigProfile:'default'`, 8등신, 가슴 설정 없음만 허용한다.
  - 저장 포즈(`bodyV1Pose.basePose`)는 기본 체형의 뼈 배치를 전제로 한다.
- **기존 검사를 그대로 쓸 수 있다.**
  - 뼈 길이·관절 제한·접촉: `doll-contact`, `body-rig`
  - 좌우: `body-sides-check`
  - 메시 점검: `doll-core-mesh-audit`
  - 성능: `doll-full-performance`

## 접근: 매개변수 체형

새 3D 모델을 만들지 않고, 기존 설계값을 체형별로 바꾸는 **체형 프로필**을 만든다.

| 축 | 값 | 바뀌는 설계값 |
|---|---|---|
| 성별 형태 `form` | `female`(현재), `male`, `neutral` | 흉곽 폭·깊이, 가슴 돌출(relief), 허리 잘록함, 골반 폭, 어깨 폭 |
| 등신 `headUnits` | 5~9.5 연속값(성인 기본 8, 아이 5~6.5) | 머리 크기 대비 몸통·팔다리 길이 비율 |
| 체격 `build` | `slim`, `average`, `heavy` | 단면 폭·깊이 배율(부위별 가중) |
| 키 `height` | 기존과 같음(0.5~3m) | 전체 크기 |

- 가슴 설정(`chest`)은 `female`의 relief 매개변수로 흡수해, 더 이상 이전 버전 몸체로 바꾸지 않는다.
- `neutral`은 성별 단서를 줄인 형태다. 설명에 성별이 없거나 그림체 유출을 줄이고 싶을 때 쓴다.
- 장면 JSON은 `actors[].body: {form, build}`를 받는다. `headUnits`는 기존 필드를 그대로 쓴다.
- 생략하면 지금과 같은 `female`, `average`, 8등신이므로 기존 장면은 바뀌지 않는다.

## 단계

### 1단계 · 체형 프로필과 메시 생성 (앱 통합 전)
- `dollProfile`과 `fullDollDesign`이 `{form, headUnits, build}`를 받도록 바꾼다.
- 기본값은 현재 설계와 바이트 단위로 같아야 한다. 기존 `preview.bin`의 shapeKey가 그대로 맞아야 한다.
- 우선 프리셋 5개를 만든다.
  - 성인 여성 8 (현재)
  - 성인 남성 8
  - 중성 8
  - 아이 5.5
  - 성인 남성 heavy
- 점검 항목:
  - 메시가 닫혀 있는지, 뒤집힌 면이 없는지 (`doll-core-mesh-audit`)
  - 소켓 안에서 관절이 회전할 여유가 있는지
  - 생성 시간(worker)
- **통과 기준:** 정면·측면·후면·사선과 같은 포즈의 실루엣 대조 캡처를 사용자가 보고 체형 차이가 읽힌다고 판단할 것. 자동 점수로 대신하지 않는다.

### 2단계 · 리그와 저장 포맷
- `bodyAsset`을 `{id:'body-v1', version:2, profile:{form, headUnits, build}}`로 확장하고, `rigProfile`에 프로필을 기록한다.
- version 1 저장 파일은 기본 프로필로 읽는다(이전 버전 호환).
- 프로필이 바뀌면 소켓 위치와 뼈 길이가 함께 바뀐다. driver 키 대응, 좌우 기준, 휴식 자세 보정이 프로필마다 맞는지 검사한다.
- `createCharacter`의 이전 버전 몸체 분기는 범위 밖 값(3~4.9등신, 9.6~12등신)에만 남긴다.
- 체형 변경 UI: 패널의 「인물 체형 설정」에 성별 형태와 체격을 추가한다. 포즈는 유지하고 몸만 바꾼다(뼈 길이는 새 체형 기준).
- **통과 기준:**
  - 모든 프리셋에서 `body-sides-check`(좌우, 이전 저장 파일 재열기, 이미지 레퍼런스 적용)와 뼈 길이 잠금을 통과할 것
  - Save → Load와 Undo/Redo로 체형과 포즈가 보존될 것

### 3단계 · 자세 프리셋 확장
- 장면 JSON `pose`에 `kneeling`(양무릎), `half-kneeling`(한쪽 무릎), `squatting`, `crouching`, `lying`(바닥에 등)을 추가한다.
- 각 프리셋은 v1 리그 관절값으로 정의하고, 모든 체형 프리셋에서 접지(발·무릎·엉덩이가 바닥에 닿음)와 자기 침투를 검사한다.
- 촬영 설명의 자세 판정(무릎 꿇음·쪼그림·누움)이 새 프리셋을 맞게 읽는지 확인한다.

### 4단계 · 성능과 사전 빌드
- 프리셋 5개는 `preview.bin` 묶음으로 미리 구워 첫 표시 지연을 없앤다. 그 밖의 연속값은 worker가 생성한다.
- 같은 장면에서 체형이 섞인 인물 8명 기준으로 렌더 시간, 그리기 호출 수, 삼각형 수를 현재와 비교한다.

### 5단계 · LLM 효과 확인 (Gemini 한도 사용, 선택)
- 남성·아이 인물을 여성 마네킹으로 줄 때와 맞는 체형으로 줄 때를 같은 방식(조건당 3회)으로 비교한다.
- 측정 항목:
  - 성별·나이 표현 오류
  - 마네킹 체형 유출(그림자·실루엣)
  - 화면 키 비율

## 범위 밖

- 얼굴, 손가락 세부, 근육 표현
- 옷 부피(코트, 치마 실루엣). 필요하면 이후 대리 부피(proxy)로 검토한다.
- 독립 검증(HGLOS) 재개. 체형 확장과 별개로 기존 v1의 외형 "미달" 판정은 그대로다. 이 계획은 그 판정을 해소한다고 주장하지 않는다.

## 위험과 대응

| 위험 | 대응 |
|---|---|
| 기본 체형이 미세하게 바뀌어 기존 장면·저장 파일이 달라짐 | 1단계에서 기본 프로필의 shapeKey와 꼭짓점이 현재와 같은지 검사로 고정 |
| 아이 등신에서 관절 소켓·팔다리 길이가 겹침 | 등신별로 소켓 반지름·팔다리 길이 하한을 두고 메시 점검 |
| 연속 매개변수로 메시 캐시가 커짐 | 프리셋 위주로 쓰고, 연속값은 0.5 단위로 양자화 |
| worker 생성이 느림 | 프리셋은 사전 빌드하고, 생성 중에는 기존 체형을 보여 준 뒤 교체 |
| 외형 판단이 주관적 | 1단계 산출물은 사용자 시각 판단으로 통과. 수치 검사는 기능에만 사용 |

## 결정이 필요한 것

1. 첫 프리셋 목록. 제안은 여성 8, 남성 8, 중성 8, 아이 5.5, 남성 heavy이며 노인 체형(굽은 자세)도 넣을지.
2. 체격과 등신을 슬라이더(연속값)로 열지, 프리셋만 둘지.
3. 진행 순서. 제안은 1단계(형상 시제품과 대조 캡처)를 먼저 보여 드리고 판단을 받은 뒤 2단계로 가는 것.

## 2단계 결과 (2026-11-10, 구현자 확인)

**앱 연결**
- 장면 JSON의 `actors[].bodyType`으로 남성, 중성, 아이, 큰 체격 남성을 지정할 수 있습니다.
- 패널의 「체형 종류」에서 선택한 인물의 체형을 바꿀 수 있습니다.

**저장 형식**
- `bodyProfile.bodyType`에 체형 종류를, `bodyAsset.profile`에 인체 자산 프로필을 적습니다.
- 기본 여성 체형은 두 필드를 쓰지 않아 기존 파일과 같습니다.
- 둘이 어긋나면 열 때 거부합니다.

**체형 메시 준비**
- 기본 외 체형은 앱 시작 후 백그라운드에서 생성합니다.
- 생성이 끝나기 전에 그 체형이 든 장면이나 프로젝트를 열면, 준비를 기다렸다가 엽니다. 시작 직후에는 최대 약 10초 걸립니다.

**체형 바꾸기**
- 저장·복원 경로를 그대로 써서 관절 회전, 위치, 키, 설명, 실행 취소 기록이 유지됩니다.

**검증** (`scripts/body-types-check.mjs`)

- 여성 → 남성 전환 시 자세·위치·키 유지, 발 접지 0

- 아이에게 이미지 레퍼런스 포즈를 적용해도 방향 유지

**남은 것**

## 3단계 결과 (2026-11-10, 구현자 확인)

**자세 프리셋** (`scene-format.js` `POSES`, 편집기 「기본 포즈」 메뉴에도 추가)

| 이름 | 메뉴 | 정의 요약 | 바닥에 닿는 곳 |
|---|---|---|---|
| `kneeling` | 무릎 꿇기 | 넓적다리 수직, 무릎 105°, 발목 45° | 두 무릎 |
| `half-kneeling` | 한쪽 무릎 꿇기 | 왼 넓적다리 96°·무릎 90°(앞발), 오른 무릎 105° | 오른 무릎, 왼발(1cm 이내) |
| `squatting` | 쪼그려 앉기 | 고관절 110°, 무릎 145°, 상체 30° | 두 발 |
| `crouching` | 웅크려 앉기 | 고관절 100°, 무릎 140°, 상체 35°, 팔이 무릎 위로 | 두 발 |
| `lying` | 바닥에 눕기 | 골반째 뒤로 90°(`body.bend`) | 등, 머리(3cm 이내) |

- 관절값은 모든 체형에 같습니다. 체형마다 팔다리 길이가 달라도 아래 기준을 통과하는 값으로 골랐습니다.
- 장면을 불러올 때는 몸 전체에서 가장 낮은 점을 `position[1]`에 맞춥니다.

**함께 고친 것**
- 바닥 맞춤(`displayedObjectBounds`)
  - 메시마다 회전된 경계 상자를 쓰다가 꼭짓점 기준으로 바꿨습니다.
  - 이전 방식에서는 무릎 꿇은 큰 체격 남성이 7.5mm 떠 있었습니다. 선 자세는 결과가 같습니다.
- 편집기에서 이름 있는 포즈를 적용할 때
  - 발목 높이 대신 몸 전체의 가장 낮은 점을 유지합니다.
  - 이전에는 무릎 꿇기를 적용하면 무릎이 바닥 아래로 들어갔습니다.
  - 무릎 꿇기에서 다른 자세로 바꿀 때도 바닥 높이가 유지됩니다.
- 촬영 설명의 상체 기울기 방향
  - 상체에 수직으로 맞춘 앞 방향과 비교하고 있어서, 상체를 많이 숙이면 "뒤로 젖힘"으로 잘못 나왔습니다.
  - 이제 수평 성분끼리 비교합니다.

**검증** (`scripts/pose-presets-check.mjs`, 5개 자세 × 5개 체형)
- 가장 낮은 점이 바닥(3mm 이내)이고, 위 표의 부위가 바닥에 닿습니다.
- 촬영 설명이 자세를 맞게 읽습니다.
  - 무릎 꿇기: 「두 무릎을 꿇음」
  - 한쪽 무릎 꿇기: 「오른쪽 무릎을 꿇음」
  - 쪼그려 앉기, 웅크려 앉기: 「쪼그려 앉음, 상체를 앞으로 18°/21° 숙임」
  - 눕기: 「등을 대고 누움(얼굴이 위)」
- 자기 침투(선 자세 대비 증가한 접촉 지점 수)
  - 여성·남성·중성·아이: 모든 자세에서 0~2
  - 큰 체격 남성: 무릎 꿇기 +5, 한쪽 무릎 +8, 웅크림 +13, 눕기 +25, 쪼그려 앉기 +97(넓적다리가 배에 눌림)
- 편집기 메뉴로 다섯 자세를 차례로 적용해도 바닥에 닿고 방향이 바뀌지 않습니다.
- 눕기·무릎 꿇기·한쪽 무릎 장면을 저장 → 다시 열기: 꼭짓점 차이 4e-16
- 캡처는 `docs/review-evidence/2026-11-10-pose-presets/`에 저장됩니다.

## 큰 체격 남성 수정 (2026-11-10, 구현자 확인 · 사용자 판단 통과)

**허리 띠**
- 원인: 몸통은 흉곽·배·골반 세 형상을 부드럽게 합친 것입니다. 골반 형상의 평평한 윗면 가장자리가 배 표면과 거의 같은 위치(폭 94 대 95)에서 만나 주름이 생겼습니다. 큰 체격 배율이 이 주름을 키웠습니다.
- 수정: `smoothWaist`가 배(y≤485)와 골반(y≥488)의 단면을, 합친 단면을 가우스로 고르게 한 하나의 윤곽에 맞춥니다. 골반의 윗줄은 그 윤곽 안쪽(×0.95)으로 넣습니다.
- 이 수정은 체형의 `form.waistSmooth`로 켜며, 지금은 큰 체격 남성만 씁니다.
- 시도했다가 버린 방법
  - 합친 단면 행만 고르게 하기: 메시는 이 행이 아니라 세 형상으로 만들어져서 효과가 없었습니다.
  - 합침 폭(blend) 넓히기: 띠는 약해졌지만 울퉁불퉁해졌습니다.

**무릎 틈 (쪼그림)**
- 원인: 다리 굵기 ×1.16을 무릎 공과 정강이 윗부분에도 그대로 적용했습니다. 무릎을 굽히면 넓어진 정강이 윗 테두리가 무릎 공 밖으로 나와 틈이 보였습니다.
- 수정: 다리가 굵은 체형(`legWidth>1`)은 무릎 공과 정강이 윗부분을 기본 크기로 두고, 그 아래로 갈수록 굵게 합니다.
- 다리가 가는 체형(아이, 중성)은 이전과 같습니다.

**팔과 몸통 겹침**
- 위팔 윗부분(겨드랑이 쪽)을 기본 굵기로 두고, 팔꿈치 쪽으로 갈수록 굵게 했습니다(`armWidth>1`일 때만).
- 이 변경은 팔이 기본보다 굵은 남성(1.1)과 중성(1.03) 체형에도 적용됩니다. 위팔 윗부분이 조금 가늘어집니다.
- 측정
  - 앱 공통 인체, 선 자세: 접촉 지점 105 → 39, 가장 깊은 곳 2.3cm → 1.6cm
  - 비교 화면 중립 자세: 24 → 7
- 어깨 폭(118 → 124, 128)과 허리 폭(1.42 → 1.32)도 시험했지만 겹침이 줄지 않아 원래대로 두었습니다.

**쪼그려 앉기**
- 선 자세 대비 증가한 접촉: +97 → +37
- 남은 것은 대부분 위 팔-몸통 접촉이고, 넓적다리-배 접촉은 깊이 약 6mm입니다.

**확인**
- 다른 체형 결과

  - 아이 체형은 바뀌지 않았습니다. 남성·중성은 위팔 윗부분만 바뀌었습니다.
- 체형 묶음을 다시 만들었고, 새로 계산한 메시와 차이 0입니다.
