# 로컬 컷신 스튜디오 검증 결과

2026년 11월 1일, Windows에서 Node.js와 Chrome으로 로컬 편집 흐름을 확인했습니다. 대상은 pose-toolkit을 확장한 현재 작업 폴더의 빌드입니다. 다른 조사 프로젝트를 실행하거나 실제 최종 이미지 생성까지 검증한 결과는 아닙니다.

## 확인한 흐름

| 항목 | 결과 | 근거 |
| --- | --- | --- |
| 배포 빌드 | 통과 | Vite 5.4.21, 46개 모듈 빌드 |
| JSON 검증 | 통과 | 예제 왕복과 잘못된 단위·관절·숫자·중복 ID·크기 등 10가지 입력 거부 |
| 예제 장면 | 통과 | 인물 2명, 소품 2개를 저장 데이터와 렌더에서 확인 |
| 관절 수정 | 통과 | UI에서 고개 회전 수정 후 실제 관절 저장값 변경, 되돌리기 |
| 소품 조작 | 통과 | 목록에서 탁자 선택 후 X 위치 수정, 소품 추가 후 되돌리기 |
| 공간 수정 | 통과 | 방 너비 6→8m가 프로젝트에 저장 |
| 카메라 컷 | 통과 | 2개에서 3개로 추가 후 저장 |
| 저장과 재열기 | 통과 | 원래 프로젝트 재열기 후 인체의 위치·회전·관절·스케일 보존, 수치 비교 허용오차 1e-8 |
| 잘못된 장면 입력 | 통과 | 단위가 틀린 JSON을 거부하고 기존 인물 상태 유지 |
| 컬러와 깊이 PNG | 통과 | 두 이미지 모두 1600×900, 실제 이미지를 열어 동일한 구도 확인 |
| 세로 PNG | 통과 | 9:16에서 900×1600 출력 |
| LLM 전달 묶음 | 통과 | 편집 상태·카메라·이미지 data URL·작화 지시문 포함 |
| 외부 연결 | 통과 | 해당 흐름의 외부 HTTP 요청 0개, 브라우저 pageerror 0개 |

최종 테스트 스크립트는 [browser-check.mjs](../scripts/browser-check.mjs), 입력 검증 테스트는 [scene-format.test.mjs](../scripts/scene-format.test.mjs)입니다. 실행 결과와 저장·렌더 증거는 `validation` 폴더에 있습니다. 로컬 정적 서버는 `127.0.0.1:3001`에서 실행합니다.

## 시각 확인

[편집 화면](../validation/editor.png), [컬러 캡처](../validation/color.png), [깊이 캡처](../validation/depth.png)를 직접 열어 확인했습니다. 단순 방 안에 두 인물·탁자·상자가 표시되고, 인물·탁자·상자의 그림자가 바닥과 탁자에 나타납니다. 출력에는 작업용 이동 핸들·축·격자가 들어가지 않습니다. 얼굴의 눈동자 시선, 손 접촉과 모든 포즈의 해부학적 정확성을 검증한 것은 아닙니다.

## 수정한 기반 동작

원래 UI의 되돌리기·다시 실행 버튼에 이벤트를 연결했습니다. 인물과 가져온 소품을 합친 목록에서 잘못 쓰이던 배열 인덱스를 고쳤습니다. 저장에 소품·방·빛·화각·카메라 목표점·컷과 정밀 관절 변환을 추가했습니다. 복원 중 중간 상태를 이력에 기록하지 않게 하고, 수치의 미세 차이로 동일한 상태가 중복 저장되는 것을 줄였습니다.

마네킹 생성자가 장면에 인체를 자동 추가하는 동작을 반영해 초기 배치 계산용 인체를 분리했습니다. 새 마네킹은 실제 바닥 Y=0에 배치하도록 보정했습니다. 모델 이름이 HTML 속성으로 들어갈 때 이스케이프하고, 입력창의 Ctrl+Z를 편집기 전체 실행 취소가 가로채지 않게 했습니다. 이전 비동기 GLB 복원 결과가 새 장면에 늦게 추가되는 것도 차단합니다.

## 남은 범위

외부 GLB 파일의 모든 형식·리깅·재질 조합, 복잡한 다인 접촉, 장시간 편집 성능, 모든 화면 크기는 검증하지 않았습니다. 현재 깊이용 사용자 셰이더는 단순 마네킹과 소품을 기준으로 확인했으며 스키닝·모프가 있는 외부 모델은 별도 검증이 필요합니다. 빌드에는 JavaScript 단일 청크가 500kB를 넘는 안내가 있으나 빌드는 통과했습니다.

LLM 자동 호출, 이미지 생성 연동, OpenPose·VRM, 컷별 포즈 분리와 접지·접촉 자동 보정은 아직 구현하지 않았습니다. 다음 작업의 순서와 완료 조건은 [고도화 설계](DESIGN.md)에 정리했습니다.
