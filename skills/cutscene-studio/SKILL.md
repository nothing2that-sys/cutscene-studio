# 컷신 스튜디오

소설의 공간·인물·행동 관계를 읽기 쉽게 보완하고, LLM의 초기 배치를 사용자가 로컬 3D에서 수정해 최종 작화로 이어간다. **3D 장면을 작업 원본으로 삼고 사용자의 수정을 보존한다.** SVG·포즈 검색·융합 이미지 생성을 매번 거치는 절차로 되돌리지 않는다.

## 기본 제작 흐름

1. **JSON 작성 — 에이전트**: 실제 앱 포맷으로 장면 JSON을 작성하고 좌표·관절·구도 관계를 자체 검토한 뒤 스키마 검증한다. 결과는 JSON 파일 링크만 제공한다. 브라우저·서버·렌더·캡처 작업은 하지 않는다.
2. **구도 수정 — 사용자**: 사용자가 편집기에서 카메라·포즈·배치·조명을 조정한다. 에이전트는 사용자의 편집을 대신 수행하거나 완료했다고 가정하지 않는다. 이 단계에서 JSON 전달로 작업을 마친다.
3. **handoff 전달 — 사용자**: 사용자가 원하는 카메라 컷을 갱신한 뒤 ‘LLM 전달 묶음’으로 저장한 `cutscene-handoff.json`을 전달한다. 이미지 생성 모델에 바로 넣을 자료가 필요하면 ‘LLM 패키지 (zip)’를 받는다(뎁스·조명·포즈 패스, 설정화, 작화 지시문 포함; [수정본과 작화](references/handoff.md)). 파일 안내를 요청하면 이 한 파일을 우선 안내한다. 컬러 PNG·깊이 PNG·정밀 편집 상태·작화 지시문이 포함되므로 별도 중복 제출을 요구하지 않는다. 외형 정본이나 원하는 화풍은 필요에 따라 함께 받는다.
4. **최종 작화 — 에이전트**: handoff와 함께 작화 요청을 받으면 [수정본과 작화](references/handoff.md)에 따라 내장 이미지를 추출·확인하고 현재 사용자 편집 상태를 기준으로 생성한다. handoff 전달만으로 생성 요청이 명확하지 않으면 파일 확인까지만 한다. 기존 PNG를 읽는 것은 새 캡처 작업이 아니다. 초기 JSON의 구도·포즈로 되돌리지 않는다.
5. **필요한 부분만 수정 — 에이전트**: 최신 작화 결과를 기준으로 요청한 얼굴·손·의상·접촉·마감 등 해당 부분부터 수정하고 다른 구도·배치·화풍은 보존한다. 실제 3D 구도 변경이 필요하면 사용자가 수정한 새 handoff를 이어받는다. 최초 JSON 작성부터 다시 시작하지 않는다.

## 요청에 맞춰 진행

- **JSON 단계의 결과물은 검토한 JSON 파일만**: 장면 JSON 제작·재현·수정 요청은 JSON 작성, 자체 검토, 스키마 검증까지 수행한다. 브라우저·편집기를 열거나 서버를 실행하지 않는다. 헤드리스 브라우저·Playwright를 포함한 렌더링, 캡처, 미리보기 이미지, 정밀 프로젝트·전달 묶음 및 촬영용 스크립트를 만들지 않는다. 사용자가 해당 작업을 별도로 명시적으로 요청했을 때만 그 범위로 진행한다. 검토를 이유로 자동 확장하지 않는다. 이 단계의 최종 응답은 JSON 파일 링크만 제공하며 컷 선정 이유·검증 로그·가져오기 안내는 요청할 때만 제공한다. handoff 기반 최종 작화와 이미지 부분 수정에는 이 JSON 전용 출력 규칙을 적용하지 않는다.
- **소설에서 컷신 준비**: 관련 원문·삽입 앞뒤·작품 지침과 실제 정본 자료를 읽고 필요한 대표 순간을 고른다. [장면 포맷](references/scene-format.md)을 읽어 장면 JSON을 저장·검증한다. 보통 1~3컷이면 충분하지만 컷 수를 강제하지 않는다. 같은 순간의 카메라 후보는 한 장면의 shots로, 시간·동작이 다른 컷은 별도 장면 파일로 만든다.
- **수정본 이어서 작업**: [수정본과 작화](references/handoff.md)를 읽고 실제 프로젝트/전달 묶음과 캡처를 확인한다. 최초 제안을 새로 생성해 덮어쓰지 않는다.
- **포즈 찾기·조합 요청**: [필요할 때만 쓰는 포즈 참고](references/pose-reference.md)를 읽는다. 기본 경로는 로컬 관절 조작이며 웹 검색·중간 이미지 생성은 요청 범위에 있을 때만 한다.
- **텍스트 콘티만 / JSON만 / 참조만**: 지정한 범위까지만 한다. 이미지 생성이 요청되지 않았으면 생성하지 않는다. 이미 허용된 연속 작업은 단계마다 다시 허락받지 않는다.

## 연출에서 유지할 것

원문에서 확실한 인물·소품·행동·공개 순서와 연출상 가정을 구별한다. 한 컷에는 하나의 대표 순간을 잡고 목적물·손·지지점·인물의 보는 대상과 행동 원인이 읽히게 한다. 원고 수정·후속 집필·본문 삽입은 별도 요청이다. 말풍선·해설·효과음 글자 없는 삽화가 기본이며 실제 정본의 외형·화풍·화면비를 따른다.

배경 마감 전에 공통 바닥·벽·깊이·층 높이·출입 경로·크기 기준, 카메라 높이·보는 방향·화각, 실제 주광 위치와 방향을 정한다. 추정한 치수와 광원은 assumptions에 기록한다. 인물을 넣기 위해 공간 원근이나 층 구조를 새로 발명하지 않는다. 카메라가 바뀌어도 장소의 기준점·소품 소유·광원은 공유한다.

인물의 height(기립 키)와 headUnits(등신 비율)를 원문·정본 또는 명시한 가정에 맞춰 정한다. 포즈를 바꿀 때 뼈 길이·키·스케일을 바꾸지 않는다. 정밀 프로젝트의 bodyProfile·boneLayout은 유지한다.

포즈는 몸통-골반-다리와 어깨-팔꿈치-손의 연결, 무게중심·발 접지·앉는 면·손과 소품 접촉·좌우·가림을 함께 본다. 마네킹의 고개 방향을 정확한 눈동자 시선 검증이라고 하지 않는다. 불확실한 손·가려진 관절은 남겨두고 확인한 것과 구별한다.

## JSON 작성과 편집기 연결

[로컬 앱 연결](references/local-app.md)에 따라 프로젝트 위치와 실제 포맷을 찾는다. helpers의 경로는 현재 SKILL.md를 기준으로 해석한다.

1. 관련 원문만 sourceText에 담고 인물·소품에 안정적인 ID를 준다. 편집기가 지원하는 포즈·관절·도형으로 표현하며 복잡한 형상은 대리 블록과 intent로 남긴다. 인물·소품의 외형은 description에, 원하는 그림체는 style에 적는다. 광원은 성격에 맞게 lighting.type을 고른다(해·창=sun, 가로등·랜턴=lamp, 펜던트·무대=spot; [장면 포맷](references/scene-format.md)).
2. 장면 파일을 새 작업 폴더에 저장한 뒤 scripts/scene.mjs의 validate 명령으로 검증한다. 명령은 로컬 앱 연결 문서를 따른다.
3. 오류가 있으면 해당 필드와 연결 관계를 고치고 다시 검증한다. 사용자가 앱의 수정 요청/검사 보고서를 주면 originalJSON과 errors·warnings를 읽고 그 원본을 수정한다. 오류는 해결하고 경고는 장면 의도와 대조하며, 문제없는 사용자 배치를 새 초안으로 덮어쓰지 않는다. 실제 앱의 좌표·yaw·관절 회전 규칙과 JSON 수치를 읽어 인물 방향, 팔의 도달 거리, 접지, 카메라 구도와 접촉 관계를 자체 검토한다. 판단이 불확실한 부분은 assumptions·intent에 기록한다. 이 검토와 스키마 검증을 실제 렌더 확인으로 표현하지 않으며, 렌더 확인을 위해 브라우저를 실행하지 않는다.
4. 검토·검증을 마친 JSON 파일 링크만 제공한다. 사용자 작업 없이 편집·렌더·캡처 완료라고 보고하지 않는다.

현재 편집기는 같은 장면의 카메라 컷들이 인물·포즈·소품을 공유한다. 다른 동작을 한 JSON의 shots로 표현하거나 컷별 포즈·접지 자동 보정·OpenPose·VRM이 구현돼 있다고 가정하지 않는다. 3D가 지원하지 않는 동작을 외형 이미지 생성으로 먼저 숨기지 않는다.

## 캡처에서 최종 작화까지

캡처는 구도·원근·깊이·인원·자세·접촉·장면 조명을, 정본 이미지는 얼굴·머리·체형·복식·화풍을 담당한다. 정본의 정면광·흰 배경·정투영에 가까운 비례를 장면에 복사하지 않는다.

“최종 이미지 생성”까지 요청되면 실제 캡처와 정본을 열고 사용 가능한 imagegen 스킬/도구로 이어간다. 특정 정본이 없으면 외형 미확정으로 구별하며 일반 인물 생성 전체를 막지 않는다. 원래 포즈 검색·융합을 다시 시작하거나 API 유료 경로로 임의 전환하지 않는다. 도구가 없으면 준비한 실제 파일·작화 지시와 미실행 상태를 제공한다.

결과를 실제로 열어 인물 동일성·좌우·시선·손발·접촉·소품·공통 공간·주광·접지 그림자를 원문과 대조한다. 오류는 해당 부분부터 수정하며 관계없는 컷·전체 페이지를 반복 생성하지 않는다. 이미지 참조만으로 픽셀 단위의 구도·포즈 보존을 보장하지 않는다. 사용자 채택과 본문 삽입 상태는 별개다.

호출 예: $cutscene-studio 이 소설에서 필요한 컷을 골라 편집기용 장면 JSON을 만들어줘.
