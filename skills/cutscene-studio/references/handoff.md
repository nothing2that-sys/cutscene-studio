# 수정된 프로젝트와 작화

## 전달받을 파일과 작업 경계

기본 입력은 사용자가 편집기에서 원하는 컷을 갱신한 뒤 내보낸 `cutscene-handoff.json` 하나다. 컬러·깊이 PNG, editorState, activeShot, render, direction이 이미 포함되므로 PNG·depth PNG·cutscene-direction의 별도 제출을 요구하지 않는다. 사용자가 별도로 제공한 더 최신 자료가 있을 때만 비교한다. 외형 정본·화풍 참고는 선택 입력이며 없으면 사용자의 요청에 맞춰 외형을 제안한다.

사용자가 handoff를 기준으로 최종 작화를 요청하면 기존 내장 이미지를 추출·열어 확인하고 이미지 생성으로 이어간다. 새 브라우저·편집기·서버를 열거나 다시 렌더·캡처하지 않는다. 생성 후에도 최신 사용자 배치와 결과를 보존하며 필요한 부분만 수정한다.

## LLM 패키지 (zip)

편집기의 「LLM 패키지 (zip)」는 이미지 생성 모델에 바로 넣을 수 있도록 같은 카메라의 패스를 나눠 담는다. 사용자가 handoff 대신 이 zip을 주면 압축을 풀어 사용한다.

| 파일 | 내용 |
| --- | --- |
| prompt.txt | 작화 지시문. 화풍 → 지킬 순서(구도, 크기·거리, 명암, 포즈, 외형) → 마네킹 따라 그리기 금지 → 카메라·조명 → 인물 목록 |
| color.png | 무채색 마네킹 렌더(구도 확인용) |
| depth.png / depth16.png | 카메라에서 표면까지 거리. 8bit는 화면 전체 1~99% 범위의 역수 거리(흰색=가까움), 16bit는 mm |
| range.png | 라이다식 거리 색(빨강=가까움→파랑=멂), 같은 거리 링, 가림 경계, 인물별 거리(m) |
| plan.png | 위에서 본 배치(위쪽=카메라가 보는 방향): 화각, 인물 위치·방향, 소품, 벽, 광원 |
| light.png | 직사광과 그림자만(주변광 제외) |
| label.png | 객체별 단색. 색과 대상은 shot.json labels |
| pose.png | 인물별 뼈대(인물 기준 왼쪽=밝은 색), 노란 광원 표시 |
| shot.json | 위 내용의 수치와 범례, 인물별 거리·명암 판정, 설정화 파일 경로 |
| refs/<id>/ | 편집기에서 인물·소품에 연결한 설정화 |

생성 모델에 넘길 때는 prompt.txt 내용과 color·depth·range·plan·light·pose 이미지를 함께 준다. 설정화가 있으면 같이 준다. label.png는 인물이 많아 누가 누구인지 헷갈릴 때 더한다. depth16.png는 수치 입력을 받는 생성기에만 쓴다.

2026-11-06 비교 실험 결과(나노바나나, 조건당 3회)는 다음과 같다.
- depth.png를 주면 인물 크기와 거리감이 정답에 맞았다(키 비율 오차 0.01~0.05). 없으면 먼 인물을 14~25% 크게 그렸다.
- light.png와 조명 설명은 color.png만으로 알 수 없는 아래 조명이나 화면 밖 광원에서만 차이를 냈다(불확실, 긍정적).
- 설명 문장만 늘리는 것은 효과가 없었다.
- 패스 이미지를 여러 장 주면 실사·3D로 끌려가므로 화풍을 맨 앞에 고정해야 한다.

pose.png·label.png·설정화의 효과는 아직 비교하지 않았다. 결과의 크기·거리감이 틀리면 depth.png가 빠졌는지 먼저 확인한다.

## 실제 상태의 우선순위

scripts/scene.mjs의 inspect 명령으로 종류와 현재 상태를 먼저 확인한다. 기본 우선순위:

1. 전달 묶음의 editorState 또는 Save로 저장한 mannequins/importedModels, studio의 실제 shots와 activeShot.
2. 내보낸 PNG 및 제공된 캐릭터 정본을 실제로 연 시각 관찰.
3. studio.initialProposal 또는 proposal은 최초 장면 제안이다. studio.document의 방·조명·제목은 현재 편집값이고 인물·소품 배치는 mannequins/importedModels가 기준이다. proposalOrigin이 legacy-current-state이면 구형 파일을 불러온 시점의 값이며 최초 제안을 복원했다고 해석하지 않는다.

사진·그림은 실제로 보인 정보, JSON은 수치 상태의 근거다. 캡처와 프로젝트가 다른 시점이면 임의로 한쪽을 최종으로 확정하지 말고 차이를 설명하고 어느 파일을 기준으로 할지 필요한 경우만 확인한다. inspect의 root position은 인체 루트이며 초기 제안의 발 기준 position과 다르다. inspect 결과만으로 시선·해부학·접촉을 검증했다고 하지 않는다.

## 전달 묶음 추출

node "<스킬>/scripts/scene.mjs" extract "<cutscene-handoff.json>" --out "<새 폴더>"

컬러/깊이 data URL을 원본 바이트 그대로 color.png/depth.png로, editorState를 project.json으로, direction을 direction.txt로 추출한다. 기존 폴더를 덮어쓰지 않는다. 추출된 파일을 실제로 열어 구도·접지·가림·광원 방향을 확인한다. 따로 제공된 PNG가 더 최신인지 대조한다.

촬영 화면은 저장한 컷 카메라이고 큰 편집 화면은 작업 카메라일 수 있다. 현재 컷 포즈는 공유하며 다른 동작 컷들은 별도 프로젝트로 보존한다. 깊이는 카메라 중심에서 표면까지의 거리를 화면 전체 1~99% 범위의 역수 거리로 칠한 값이다(2026-11-10 이전은 인물·소품 범위의 선형 값). 가까울수록 밝고 배경은 검정이다. 실제 범위(m)는 packet.render.depthRangeM, 화면비·출력 크기는 packet.render를 따른다(2026-11-06 이전 묶음은 선형 카메라 Z였다). 생성기에서 지원할 때만 구조 입력으로 사용한다. 해당 모델이 요구하는 정규화와 다를 수 있다.

## 작화 지시

전달 묶음의 `anatomyReferences`가 있으면 인물 ID별 가슴 체적 중심의 월드 좌표와 촬영 화면 좌표를 함께 참고한다. 좌표는 이미지 왼쪽 위 원점의 0~1 비율이며 `inFrame`은 프레임 안 여부만 나타내고 가림 여부를 보장하지 않는다. 유두 위치로 해석하지 않는다. 실제 캡처와 대조해 어깨·흉곽에 대한 높이·좌우 간격·원근을 유지하고, 팔·의상에 가려진 부분을 임의로 드러내거나 다른 위치에 새로 배치하지 않는다. Save 파일만 있으면 `bodyProfile.chest`가 설정이며 화면 좌표를 임의로 만들어 내지 않는다.

원문 관련 순간과 공개 순서, 인물 ID와 역할, 행동과 물건을 쥔 손, 접촉과 지지점, 카메라·공간·주광을 짧게 전달한다. 캡처는 구조, 정본은 외형·화풍의 기준이다. 외형 정본의 조명·배경을 장면에 복사하지 않는다. 임의 반전·새 인물·새 사건·설명 글자를 추가하지 않는다.

캐릭터 정본에 없는 외형은 시안으로 구분한다. 생성 요청이 있으면 사용 가능한 imagegen 스킬을 읽고 실제 확인한 캡처·정본을 참조 입력으로 전달한다. 프롬프트 준비 요청이면 파일과 지시문까지만 만든다. 실제 생성·관찰·수정과 준비 상태를 구별한다.

결과의 원근·인체 크기·접지·손/물건·정본 동일성·시선·명암·그림자를 확인한다. 생성 결과가 handoff에서 벗어났다면 기존 캡처를 기준으로 해당 부분을 수정하며 사용자에게 구도를 다시 만들도록 요구하지 않는다. 실제 3D 공간·카메라 자체의 변경이 필요한 경우에만 사용자가 편집 후 새 handoff를 전달하도록 안내한다. 에이전트가 임의로 브라우저를 열어 수정·재촬영하지 않는다. 외형·마감 문제는 최신 결과의 기존 구도를 보존해 국소 수정한다. 새 버전으로 저장하고 관계없는 부분이나 전체 제작 단계를 반복하지 않는다. 이미지 참조와 부분 수정으로도 픽셀 단위의 포즈·구도 고정을 보장하지 않는다.

## 앱의 JSON 오류 보고서

앱의 LLM 수정 요청 복사 또는 보고서 저장으로 받은 입력은 reportVersion=1, originalJSON, errors, warnings, source, inputKind를 포함한다. scripts/scene.mjs inspect는 validation-report로 읽는다. originalJSON은 문법 오류까지 보존한 문자열이며 errors의 path·code·message·expected·actual이 수정 근거다. 문법 오류의 line/column은 파서가 위치를 제공한 경우에만 있다.

원본을 기준으로 오류 필드와 연결된 관계만 고친다. unknown field는 앱이 지원하는 필드로 정정하며 앱 포맷을 임의 확장하지 않는다. 경고는 방 밖 배치·바닥 아래 높이·벽 뒤 카메라·기본값 사용 등으로, 연출상 의도가 있으면 무조건 제거하지 않는다. inputKind=project이면 라디안·관절·소품·카메라의 실제 수정 상태를 보존한다. 검증 후 같은 종류의 전체 JSON 파일 링크만 반환한다. 수정 설명은 요청할 때만 제공한다. 통과가 시각적인 접지·시선·가림 검증을 뜻하지는 않는다.
