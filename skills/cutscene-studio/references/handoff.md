# 수정된 프로젝트와 작화

## 실제 상태의 우선순위

scripts/scene.mjs의 inspect 명령으로 종류와 현재 상태를 먼저 확인한다. 기본 우선순위:

1. 전달 묶음의 editorState 또는 Save로 저장한 mannequins/importedModels, studio의 실제 shots와 activeShot.
2. 내보낸 PNG 및 제공된 캐릭터 정본을 실제로 연 시각 관찰.
3. studio.document 또는 proposal은 최초 장면 제안이다. 사용자가 옮긴 결과와 다를 수 있다.

사진·그림은 실제로 보인 정보, JSON은 수치 상태의 근거다. 캡처와 프로젝트가 다른 시점이면 임의로 한쪽을 최종으로 확정하지 말고 차이를 설명하고 어느 파일을 기준으로 할지 필요한 경우만 확인한다. inspect의 root position은 인체 루트이며 초기 제안의 발 기준 position과 다르다. inspect 결과만으로 시선·해부학·접촉을 검증했다고 하지 않는다.

## 전달 묶음 추출

node "<스킬>/scripts/scene.mjs" extract "<cutscene-handoff.json>" --out "<새 폴더>"

컬러/깊이 data URL을 원본 바이트 그대로 color.png/depth.png로, editorState를 project.json으로, direction을 direction.txt로 추출한다. 기존 폴더를 덮어쓰지 않는다. 추출된 파일을 실제로 열어 구도·접지·가림·광원 방향을 확인한다. 따로 제공된 PNG가 더 최신인지 대조한다.

촬영 화면은 저장한 컷 카메라이고 큰 편집 화면은 작업 카메라일 수 있다. 현재 컷 포즈는 공유하며 다른 동작 컷들은 별도 프로젝트로 보존한다. 깊이는 선형 카메라 Z, 가까울수록 밝고 배경은 검정이다. near/far·화면비·출력 크기는 packet.render를 따른다. 생성기에서 지원할 때만 구조 입력으로 사용한다. 해당 모델이 요구하는 정규화와 다를 수 있다.

## 작화 지시

원문 관련 순간과 공개 순서, 인물 ID와 역할, 행동과 물건을 쥔 손, 접촉과 지지점, 카메라·공간·주광을 짧게 전달한다. 캡처는 구조, 정본은 외형·화풍의 기준이다. 외형 정본의 조명·배경을 장면에 복사하지 않는다. 임의 반전·새 인물·새 사건·설명 글자를 추가하지 않는다.

캐릭터 정본에 없는 외형은 시안으로 구분한다. 생성 요청이 있으면 사용 가능한 imagegen 스킬을 읽고 실제 확인한 캡처·정본을 참조 입력으로 전달한다. 프롬프트 준비 요청이면 파일과 지시문까지만 만든다. 실제 생성·관찰·수정과 준비 상태를 구별한다.

결과의 원근·인체 크기·접지·손/물건·정본 동일성·시선·명암·그림자를 확인한다. 공간/카메라 문제가 원인이면 3D 상태에서 고치고 다시 캡처한다. 외형/마감 문제는 기존 구도를 보존해 국소 수정한다. 모든 단계의 전체 재생성을 반복하지 않는다.

## 앱의 JSON 오류 보고서

앱의 LLM 수정 요청 복사 또는 보고서 저장으로 받은 입력은 reportVersion=1, originalJSON, errors, warnings, source, inputKind를 포함한다. scripts/scene.mjs inspect는 validation-report로 읽는다. originalJSON은 문법 오류까지 보존한 문자열이며 errors의 path·code·message·expected·actual이 수정 근거다. 문법 오류의 line/column은 파서가 위치를 제공한 경우에만 있다.

원본을 기준으로 오류 필드와 연결된 관계만 고친다. unknown field는 앱이 지원하는 필드로 정정하며 앱 포맷을 임의 확장하지 않는다. 경고는 방 밖 배치·바닥 아래 높이·벽 뒤 카메라·기본값 사용 등으로, 연출상 의도가 있으면 무조건 제거하지 않는다. inputKind=project이면 라디안·관절·소품·카메라의 실제 수정 상태를 보존한다. 검증 후 같은 종류의 전체 JSON 파일을 반환하고 어떤 오류를 고쳤는지 짧게 설명한다. 통과가 시각적인 접지·시선·가림 검증을 뜻하지는 않는다.
